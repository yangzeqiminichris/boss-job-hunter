# Boss Job Hunter

帮用户在 Boss直聘上搜索职位，自动过滤薪资、HR活跃度、发布时间，结果按公司分组展示。

## 前提：检查 MCP 是否可用

在开始任何操作之前，先确认 `boss-job-hunter` MCP Server 已连接。如果没有看到 `login` 和 `search_jobs` 工具，告诉用户：

> boss-job-hunter MCP 未配置，请先按照 README 完成安装：
> https://github.com/yangzeqiminichris/boss-job-hunter

---

## 第一步：检查登录状态

检查 `~/.boss_job_hunter/cookies.json` 是否存在。

- **存在** → 直接进入第二步搜索
- **不存在** → 提示用户登录：

> 需要先登录 Boss直聘。我来打开浏览器，你在里面正常登录（扫码或账号密码都可以），登录成功后会自动关闭。

调用：
```
login(method="browser")
```

登录成功后继续。

---

## 第二步：收集搜索参数

如果用户已经在消息里说清楚了（比如"上海 Java 工程师 20-30K"），直接提取参数，不要再问。

如果信息不完整，**一次性**问清楚必要的参数：

> 请告诉我：
> - 想找什么职位？（如：Java工程师、产品经理）
> - 在哪个城市？
> - 期望薪资范围？（如：20-30K）

可选参数不用主动问，使用默认值：
- `salary_overlap`: 0.5（薪资有 50% 交集即可）
- `posted_within_days`: 30（近 1 个月发布）
- `hr_active_within_days`: 7（HR 本周内活跃）
- `sort_by`: "hr_active"（按 HR 最近活跃排序）
- `max_results`: 50

如果用户提到了公司规模要求（如"大厂"、"100人以上"），加上 `company_size` 过滤。

---

## 第三步：执行搜索

调用 `search_jobs`，把参数填入。示例：

```
search_jobs(
  keyword="Java工程师",
  city="上海",
  salary_min=20,
  salary_max=30,
  hr_active_within_days=7,
  posted_within_days=30,
  sort_by="hr_active"
)
```

---

## 第四步：展示结果

把 JSON 结果转成易读的格式，每个公司一块：

```
📦 字节跳动  |  互联网  |  10000人以上  |  已上市
   福利：年终奖 · 弹性工作 · 五险一金

   💼 Java工程师         25-40K·13薪
      HR 3天前活跃 · 2周前发布
      🔗 https://www.zhipin.com/...

   💼 后端开发工程师      30-50K
      HR 今日活跃 · 1周前发布
      🔗 https://www.zhipin.com/...

---

📦 美团  |  互联网  |  10000人以上  |  已上市
   ...
```

如果有"薪资面议"的职位，放在最后展示，标注需要自行确认薪资。

---

## 第五步：结果为空时的处理

如果没有结果，告诉用户当前过滤条件，并提供具体建议：

> 没找到符合条件的职位。可以尝试：
> - 把薪资交集比例放宽（比如说"放宽薪资条件"）
> - 把 HR 活跃时间放宽到 14 天
> - 换个关键词试试

## 交互示例

**用户：** 帮我在上海找 Java 工程师，薪资 20-30K

**你：**（直接搜索，不再问问题）→ 展示结果

---

**用户：** 帮我找工作

**你：** 请告诉我想找什么职位、在哪个城市、期望薪资范围？

---

**用户：** 结果太少了，放宽一下

**你：**（把 `salary_overlap` 降到 0.3，`hr_active_within_days` 放宽到 14）→ 重新搜索展示

---

## 注意事项

- 不要把原始 JSON 直接输出给用户，始终格式化展示
- 链接要保留，方便用户直接点击投递
- 如果用户说"按公司规模排序"，加上 `sort_by="company_size"`
- 如果用户说"只要大公司"，加上 `company_size=["1000-9999人","10000人以上"]`
- Cookie 失效时，重新引导登录
